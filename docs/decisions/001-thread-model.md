# ADR 001：第一版采用每路输入线程加每路处理线程

## 状态

已接受。

## 背景

项目需要同时处理多路 RTSP，并在推理变慢或单路断流时保持其他流运行。直接把读取、推理和输出放在同一个线程中，会让队列无法发挥作用；一开始引入共享推理线程池，又会增加调度、顺序和生命周期复杂度。

## 决策

第一版每路使用：

```text
输入/解码线程 → 每路有界队列 → 每路处理线程 → 异步输出
```

队列默认使用 `drop_oldest` 保持实时延迟，MP4 离线模式可切换为阻塞策略。

## 原因

- 每路故障隔离清晰。
- 便于调试时间戳、内存所有权和停止流程。
- 能真实验证队列限流和丢帧策略。
- 四路规模下实现复杂度可控。

## 后续变化条件

当单机路数、推理耗时或 GPU 利用率证明需要共享调度时，再引入 `InferenceScheduler`。引入前必须补充公平调度、结果顺序和线程池资源预算测试。
