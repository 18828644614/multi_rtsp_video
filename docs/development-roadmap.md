# 开发路线

每个阶段都必须有可运行产物和明确退出条件，不以“代码写完”作为验收标准。

## 阶段 0：范围、依赖与测试资产

- 固定第一版目标、输入规格和建议性能基线。
- 准备本地 MP4、模型文件和模型 manifest。
- 安装并验证编译器、CMake、FFmpeg、OpenCV、ONNX Runtime 和 GoogleTest。
- 准备依赖版本记录和环境检查脚本。

退出条件：按照 `docs/dependency.md` 能确认环境，测试视频和模型许可证清晰。

## 阶段 1：项目骨架与配置

- 创建 CMake 工程和 CMake Preset。
- 添加 `src`、`include` 和 `tests` 模块。
- 实现配置读取、schema 校验、日志入口和版本信息。
- 建立停止令牌、错误码和基础状态类型。

退出条件：空工程能构建，错误配置能在启动前被拒绝，程序能输出版本信息。

## 阶段 2：单路 MP4 解码

- 打开 MP4 并查找视频流。
- 使用 `avcodec_send_packet/receive_frame` 解码。
- 实现 `FramePacket` 和 PTS/时间基转换。
- 将 `AVFrame` 转换为 `cv::Mat`。
- 增加资源释放和停止测试。

退出条件：单路 MP4 能连续读取，输出帧尺寸、序号、PTS 和时间戳，Sanitizer 无明显错误。

## 阶段 3：单路目标检测

- 加载并校验 ONNX 模型 manifest。
- 完成预处理、推理、后处理和 NMS。
- 绘制检测框并输出结构化检测结果。
- 记录推理耗时和处理 FPS。

退出条件：单路 MP4 能生成稳定的标注视频和符合 schema 的 JSONL。

## 阶段 4：Tracker 与业务事件

- 实现简化 Tracker 和 `track_id`。
- 增加 ROI、目标计数、越线和区域进入规则。
- 增加事件冷却、去重和告警截图。
- 固定事件 JSON Schema。

退出条件：同一目标不会在冷却时间内重复告警，越线事件包含方向和轨迹 ID。

## 阶段 5：RTSP 与单路重连

- 使用 MediaMTX 将 MP4 按实时速度发布为 RTSP。
- 实现连接超时、读取超时、断流识别和指数退避。
- 明确 MP4 EOF 与 RTSP Disconnect 的不同处理。

退出条件：停止并恢复 RTSP 发布后，系统能在目标时间内重新进入 Running。

## 阶段 6：多路并发与有界队列

- 为每路流建立独立 `StreamWorker`。
- 增加每路有界队列和丢帧策略。
- 处理不同分辨率和帧率。
- 增加单路故障隔离和每路独立指标。

退出条件：至少四路本地模拟 RTSP 并行运行，一路失败不影响其他路，队列和内存保持有界。

## 阶段 7：可观测性、故障注入与性能

- 增加 P50/P95/P99 延迟、队列峰值、丢帧原因和重连恢复时间。
- 增加输入失败、推理变慢、输出失败和磁盘异常测试。
- 使用 Sanitizer、调试器和性能分析工具检查资源问题。
- 根据基线调整模型输入尺寸、线程数、队列长度和输出策略。

退出条件：完成固定测试矩阵，生成可复查的性能记录，连续运行无明显内存和线程增长。

## 阶段 8：工程化交付

- 保存架构图、运行截图和测试原始记录。
- 补充构建、运行、故障排查和限制说明。
- 只记录实际实现的功能和实际测得的性能数字。
- 准备围绕线程模型、丢帧策略、时间戳和重连机制的面试说明。
