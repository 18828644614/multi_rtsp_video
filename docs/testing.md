# 测试与验证方案

## 1. 测试原则

- 单元测试不依赖真实 RTSP、真实模型和外部服务。
- 集成测试使用固定视频、固定模型和固定配置。
- 故障测试必须记录故障注入时间、恢复时间和最终状态。
- 性能测试记录硬件、软件版本、模型、输入规格和测试时长。

## 2. 测试层级

### 单元测试

- 配置读取、默认值、字段校验和环境变量替换。
- 时间戳与时基转换。
- 帧序号和延迟计算。
- 边界框裁剪、坐标映射和 NMS。
- ROI、越线方向和事件冷却。
- Tracker 的创建、匹配、超时和清理。
- 有界队列入队、出队、停止和丢帧。
- 重连状态机和退避时间计算。

### 模块测试

- FFmpeg 能否打开有效 MP4。
- 不存在的输入是否返回明确错误。
- 不支持的编码格式是否安全退出。
- `AVFrame` 到 `cv::Mat` 的尺寸、颜色和 stride 是否正确。
- 模型输入输出签名是否符合 manifest。
- 输出视频能否被播放器重新打开。
- JSONL 每行是否符合输出 schema。

### 集成测试

- 单路 MP4：解码、推理、跟踪、事件、绘制和输出。
- 单路 RTSP：连接、读取、推理和输出。
- 多路 RTSP：至少四路同时运行。
- 一路断流：其他流继续运行。
- 恢复发布：断流流在目标时间内重连。
- 进程收到停止信号：所有线程、队列和媒体资源都释放。

### 故障注入与压力测试

- 输入连接失败、读取超时和连续解码错误。
- 人为降低推理速度，验证队列上限和丢帧策略。
- 不同分辨率、帧率、像素格式和文件结束行为。
- 磁盘写入失败、输出目录不可用和输出文件过大。
- 长时间运行并观察内存、线程和句柄是否增长。
- 增加流数量，记录吞吐和延迟拐点。

## 3. 指标定义

```text
端到端延迟 = 处理完成单调时钟 - 帧进入系统单调时钟
丢帧率 = 丢弃帧数 / (接收帧数 + 丢弃帧数)
处理 FPS = 处理完成帧数 / 统计窗口秒数
重连恢复时间 = 重新发布时间到再次进入 Running 的秒数
```

所有延迟至少记录 P50、P95、P99 和最大值；平均值只能作为补充指标。

## 5. 验收测试清单

- [ ] 干净目录可以完成构建。
- [ ] 配置错误能在启动阶段被发现。
- [ ] 单路 MP4 可以输出标注视频和 JSONL。
- [ ] 单路 RTSP 可以连接并完成检测。
- [ ] 四路本地模拟 RTSP 可以同时运行。
- [ ] 断开一路流后其他流继续运行。
- [ ] 恢复流后能够自动重连。
- [ ] 越线事件包含稳定的 `track_id` 且不会重复告警。
- [ ] 队列不会无限增长。
- [ ] P95 延迟和丢帧率符合配置的验收阈值。
- [ ] 程序停止时能够释放线程和媒体资源。
- [ ] 性能数字来自可重复测试记录。
