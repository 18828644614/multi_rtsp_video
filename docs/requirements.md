# 需求与验收标准

## 1. 项目目标

实现一个可运行的多路视频分析系统，从本地 MP4 或 RTSP 输入视频，对帧执行目标检测、跟踪和事件分析，并输出检测结果、事件记录和运行指标。

项目重点不是模型训练，而是展示以下工程能力：

- FFmpeg 解封装、解码和时间戳处理。
- C++ 多线程、队列限流和资源生命周期管理。
- ONNX Runtime 推理与模型输入输出适配。
- RTSP 断流检测、重连和单路故障隔离。
- 可重复的测试、性能记录和问题定位。

## 2. 第一版范围

### 输入

- 单个或多个本地 MP4 文件。
- MediaMTX 发布的本地 RTSP 流。
- 经过授权的公开测试 RTSP 流。

### 检测与跟踪

- 人员、汽车、卡车和公交车检测。
- 检测框、类别、置信度和帧序号输出。
- 可配置置信度阈值、NMS 阈值和目标输入尺寸。
- 第一版支持简化目标跟踪，为越线和事件去重提供稳定的 `track_id`。

### 事件

- 每帧目标数量统计。
- 矩形 ROI 内目标数量统计。
- 基于轨迹的越线事件。
- 区域进入和区域离开事件。
- 告警截图和 JSON Lines 事件记录。
- 事件冷却、去重和最小持续时间可配置。

### 稳定性

- 输入连接失败时重试。
- RTSP 断流后自动重连。
- 解码错误达到阈值后重建输入上下文。
- 使用有界队列限制内存增长。
- 队列积压时优先丢弃旧帧，保持实时延迟。
- 单路流异常不应直接终止其他流。
- 程序收到停止信号后能够停止所有线程并释放媒体资源。

## 3. 非功能需求

### 建议的第一版性能基线

实际验收时必须把下表中的环境替换为真实测试记录；这里的数值是第一版的建议基线，不是未经测试的承诺。

| 指标 | 建议基线 |
|---|---|
| 并发路数 | 4 路本地模拟 RTSP |
| 输入规格 | 每路 720p、25 FPS |
| 端到端延迟 | P95 不高于 500 ms |
| 重连恢复 | 发布恢复后 10 秒内重新进入 Running |
| 连续运行 | 至少 30 分钟无持续内存增长 |
| 队列策略 | 每路按帧数和毫秒上限双重限制 |
| 统计精度 | 所有指标按 `stream_id` 独立记录 |

### 工程要求

- 使用 C++17 或更高版本，并使用 CMake 构建。
- MP4 和 RTSP 共享同一套解码后的处理链路。
- 配置项不硬编码在业务代码中。
- 日志包含时间、级别、`stream_id`、模块名和错误原因。
- 密码、访问令牌和私人 RTSP 地址不进入仓库。
- 支持在干净目录按文档完成配置、构建和最小运行验证。

## 4. 第一版验收标准

### 基础链路

- 能打开 MP4 并连续解码。
- 能正确记录 PTS、时间基和单调时钟时间。
- 能执行 ONNX 推理并输出类别、置信度和坐标。
- 能生成带检测框的输出视频。
- 能输出符合 `docs/output-schemas.md` 的 JSON Lines。

### 多路处理

- 至少四路本地模拟 RTSP 同时运行。
- 每路具有独立状态、队列、统计和输出路径。
- 不同分辨率和帧率不会共享错误的转换上下文。
- 单路失败不会直接终止其他路。

### 事件语义

- 越线事件包含 `track_id`、方向和事件时间。
- 同一目标在冷却时间内不会重复产生相同事件。
- 无检测结果时输出空结果，不产生误告警。
- 断流重连后轨迹状态按配置清空或恢复，行为有测试覆盖。

### 异常恢复

- 停止一个 RTSP 发布进程后，系统记录断流状态。
- 重新发布后，系统按退避策略自动重连。
- 连续解码错误达到阈值后重建输入上下文。
- 队列积压时内存保持有界，并记录丢帧数量和原因。

### 性能记录

- 记录输入、解码、推理和输出 FPS。
- 记录 P50/P95/P99 延迟和最大延迟。
- 记录接收帧、处理帧、丢帧及丢帧率。
- 记录 CPU、内存、队列深度、重连次数和最近错误。
- 简历中的性能数字必须能关联到测试配置和原始记录。

## 5. 明确不做

- 不在本项目中训练目标检测模型。
- 不实现完整的用户登录、权限系统和多租户。
- 不实现云端存储、分布式调度和集群高可用。
- 不把 GUI 作为第一阶段的必需功能。
- 不访问没有授权的摄像头或私人视频流。

## 6. 主要风险

| 风险 | 影响 | 应对方式 |
|---|---|---|
| 模型推理速度不足 | 延迟增长、队列积压 | 降低输入尺寸、跳帧、优化模型或使用 GPU |
| RTSP 网络抖动 | 断流或延迟增长 | 读取超时、指数退避、有界队列 |
| 多路线程竞争 | FPS 不稳定 | 明确线程模型，限制线程池和队列规模 |
| 时间戳处理错误 | 延迟和事件时间不可信 | 同时保存 PTS、墙上时钟和单调时钟 |
| 事件依赖跟踪 | 越线重复或漏报 | 将 Tracker 作为独立模块并做规则测试 |
| 第三方依赖配置困难 | 无法构建 | 固定版本矩阵，提供 CMake Preset 和环境检查脚本 |
